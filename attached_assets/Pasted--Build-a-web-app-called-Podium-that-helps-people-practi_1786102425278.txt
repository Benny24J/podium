

Build a web app called **"Podium"** that helps people practice public speaking and articulation by having them research and speak on random topics under timed conditions.

### User Flow
1. User lands on a home screen and picks a **topic category**.
2. User clicks **"Shuffle"** — the topic name should rapidly cycle through several different topic titles in place, like a slot-machine text effect, for about 1-2 seconds, gradually slowing down before landing on the final selected topic. This should NOT be a circular/carousel spinning-wheel visual — just text cycling quickly in the same spot and then settling.
3. User picks a **research timer** length: 10 min, 15 min, 20 min, 30 min, 45 min, or 60 min.
4. A countdown timer runs while they research the topic (show a progress ring or bar, plus the topic, category, and its "angles to explore" — see Topic Bank section — visible the whole time).
5. When research time ends (or they end it early), user picks a **speaking timer** length: 1 min, 2 min, 5 min, 10 min, or 15 min.
6. User clicks "Start Speaking" — the app begins recording (audio and video via webcam/mic) and counts down the speaking timer.
7. When the timer ends (or they stop early), recording stops automatically.
8. User lands on a **results screen** where they can play back their recording, see how long they spoke, which topic/category it was, and re-do the exercise.
9. Keep a simple **history log** of past sessions (topic, category, date, research time used, speaking time used, and a link to that recording).
10. Add a clear, always-visible **"Back" / "Choose a different topic"** option at every stage before recording starts, so users can back out to category/topic selection instead of only moving forward. Once recording has started, disable back navigation or prompt "are you sure you want to discard this recording?" before allowing it, to avoid accidental data loss.

Generate the 3-4 angles-to-explore for each topic yourself, appropriate to that topic.

### Design
- Keep the existing color palette as-is — don't change the colors already in use. Just make sure they're applied consistently across every screen (home, category select, research mode, recording mode, results).
- Clean, modern layout. Mobile and desktop friendly.
- Clear visual distinction between "research mode" (calm, focused) and "recording mode" (make it obvious they're live — recording indicator, red dot, etc.)
- Big, obvious buttons for shuffle and timer selection — minimal friction between "pick topic" and "start."

### Technical Notes
- Use the browser's microphone and camera APIs (`getUserMedia`, `MediaRecorder`) for recording; request permission clearly before the speaking timer starts.
- Set up basic authentication (email sign-in is fine) so session history and recordings persist per user across visits.
- Use Supabase (or another Postgres-backed service) for the topics database, user accounts, and storing session metadata + recording files/links.
- This app runs in-browser — stick to standard web APIs and npm packages that work in a browser sandbox (no Node-only or native dependencies for anything client-facing).
